# 资料解析与硬件核对

先询问或读取资料适用的产品、硬件版次、变体和生效范围。目录清单用来找到资料。提取内容后，在登记表写文件路径、版本、散列及可复查定位，注明工具、视图及未读范围。

| 输入 | 阅读与复核方法 | 能力不足时索取 |
| --- | --- | --- |
| PDF 原理图、PNG、JPG、SVG | 用可用的 PDF 文本、页渲染和视觉能力。SVG 核对连接线、节点和标签的页面位置。区分同名网络作用域、跨页端口和网桥。 | 清晰分页面、可信 PDF、网表、引脚表和板版本 |
| PCB、EDA 工程、网表和 BOM | 用对应 EDA 版本读取可解析原生格式或官方导出。比对原理图引用标号、PCB 板版次、适配 BOM 的装配选项及网络名称。 | 中性网表、Gerber 及绘图、装配输出、BOM 和网络或测试点表 |
| 器件 Datasheet、Reference Manual、Errata、选型手册 | 核对型号后缀、封装、修订和发布日期，查适用章节和正常工作条件。外部器件另核对上电、总线时序、地址位格式及复位值。 | 精确料号、官方文档编号、版本、目标页及 SDK 版本 |
| DOC、DOCX、PDF、MD、TXT、PPT、PPTX、XLS、XLSX、CSV | 用实际客户端或可用解析器读取。表格记录工作表/单元格、值和公式语义，PPT 检查备注及图形，扫描版 PDF 用 OCR 并回看页图。 | DOCX、PDF、CSV、多页图片或带表头的结构化导出 |
| JSON、XML、YAML、INI、Draw.io、Visio | 使用相应解析工具。Draw.io 检查是否压缩、页面以及形状连线，Visio 优先使用可用查看器或导出。结构化格式内另核对范围、引用及单位。 | 未压缩 XML、PDF/SVG/PNG、连接关系表 |
| C/C++、工程配置、Keil、IAR、CMake、Make、启动与链接文件、SDK/BSP/库/测试 | 结合项目定义、活动目标、宏、include 路径、启动/链接、构建日志及入口读实际代码。确认生成输入和手写文件边界。 | 激活的目标配置、可重现的构建命令和版本、编译/链接日志 |

需求、设计、协议和测试文档需提取可验证断言、前置条件、上下限、异常路径和验收标准。流程、时序、状态机、软件架构和系统框图须核对方向、触发条件、单位、初始/异常状态及回退路径。

## 原理图到固件配置

1. 识别板号、版本、MCU 型号及封装。按页盘点供电、参考地、电压域、复位、Boot/调试、晶振与时钟源，核对专用脚及复位默认态。
2. 按器件和网络建立引脚表，记录页和坐标、引脚号、GPIO、网络名、方向、电气类型、上拉/下拉、复用、有效电平及启动安全态。检查未装器件、短接选件和电平转换方向。
3. 逐条确认 UART、SPI、I2C、CAN 等总线连线、外设实例、收发器、片选/地址、终端、时序与电气约束。核对 IRQ 信号、边沿、极性和共享来源。DMA 请求、IRQ 优先级、时钟树及复用另核对该芯片的官方表和 SDK，并确认无资源冲突。
4. 将图面读到的标签标记为视觉候选。将受批准版次和网表等独立连接证据支持的记录标记为已核对。用精确料号和芯片版本的官方资料核对能力，标明每个结果的确认级别。
5. 生成可供 BSP/驱动使用的资源表。建议列为 `信号 | 实际引脚 | 网络/设备 | 实例/复用 | 方向和电气 | IRQ/DMA | 来源 + 定位 | 确认状态`，写清冲突和待核对项目。波形或探针测量随板版次、仪器设置和负载记录。

遇到专有格式或渲染不完整，指出受限的文件与范围，获取可解析导出，先完成独立的文档或代码核对。资料差异进入 [一致性与影响分析](consistency.md)。
