# 多 Agent 协作与恢复

Project Coordinator 负责计划、模块划分、硬件和接口共同基线、调度、冲突处理、集成及外部交付。小任务由同一 Agent 顺序承担需要的职责。用实际可用并获授权的协作工具，模板的存在只是可供注册或转交的角色定义。

## 注册与调度

| 角色 | 典型输入 → 交付 |
| --- | --- |
| `project_explorer` | 仓库与初始描述 → 活动目标、代码入口、证据和缺口 |
| `hardware_analyst` | 原理图、网表、BOM、手册 → 资源映射、证据定位、冲突 |
| `architecture_designer` | 已确认需求与能力 → 层和模块、接口、资源与 ADR |
| `driver_developer` | 硬件事实与契约 → BSP/Driver 改动和边界测试 |
| `firmware_developer` | 需求与版本化接口 → Service/Application 及验证 |
| `rtos_specialist` | 调度预算与内核配置 → OS 适配、并发和资源证据 |
| `test_engineer` | 需求、构建入口及硬件条件 → 测试、复现步骤、结果 |
| `code_reviewer` | 基线和差异 → 可定位的审查项、范围与风险 |
| `documentation_manager` | 已确认的决策与证据 → 权威记录及下游同步 |

模板在 [`agents/specialists/`](../../agents/specialists/)。支持自定义角色的 Codex 从目标仓库 `.codex/agents/` 或 `~/.codex/agents/` 读取独立 TOML。选取必要角色，在授权下复制到目标配置目录并保留现有同名文件。无需覆盖模型或宿主权限。调度接口没有命名角色时，用可用的通用子 Agent 携带明确职责与输入；宿主没有子 Agent 时顺序执行同样的任务包。项目级 `[agents]` 配置按运行时文档和授权调整，模板本身可以独立使用。[Codex 自定义子 Agent](https://learn.chatgpt.com/docs/agent-configuration/subagents#custom-agents)

## 任务包和所有权

1. 在 `AGENT_REGISTRY.md` 登记角色、责任人、模块、逻辑会话 ID、活动任务、基线和已观察到的运行时线程 ID（若提供）。在 `MODULE_STATUS.md` 维护任务依赖和写入范围。
2. 锁定公共接口版本及验收用例后分派。任务包写模块/需求 ID、目标、输入资料和精确定位、基线提交和接口版本、目录及明确允许写的文件、读权限范围、禁改的共享文件、验证命令、报告路径、阻塞条件。
3. 一个文件同一时间有一个写入者。公共头、项目配置、链接脚本和跨模块记录由协调者单独负责或显式转交。接口变更须登记影响、通知受影响模块、确认版本和重验调整后的消费者。可再拆分有独立输入输出和所有者的子任务。
4. 子 Agent 回报完成范围、改动、可定位证据、命令及结果、未解决事项、分支/提交和后续动作。冲突登记 P0/P1/P2，影响某链路时标出被阻断的任务及可继续任务。
5. 协调者检查实际 diff、测试证据和变更归属，复核公共契约和依赖。集成后跑消费者和系统回归，再更新状态。并行完成的模块需要独立的集成证据。

## Git 策略

| 规模 | 默认选择 | 约束 |
| --- | --- | --- |
| 小 | 共享工作区 | 写集合无重叠。协调者管理共有文件和集成入口。 |
| 中 | 独立 Branch | 记录基线和分支。一个物理 checkout 中的分支切换需串行，真正同时写入使用独立工作目录。 |
| 大 | 独立 Worktree | 宿主支持且仓库授权时创建，明确工作目录、临时产物、生命周期和分支，检查共享生成物。 |

集成前读取提交和工作树状态、所有权、文件及接口冲突、构建、测试和依赖关系。遇到用户修改或无法对齐的基线保留现状并协调。避免未经授权的 `reset --hard`、强推、工作区清理或丢弃其他工作树内容。

## 逻辑会话与交接

逻辑模块会话由稳定 `MOD-...`、项目链接、`MODULE_CONTEXT.md`、`DESIGN.md`、`INTERFACE.md`、问题、`TEST_REPORT.md` 和 [`HANDOFF.md`](../../templates/handoff/HANDOFF.md) 标识。实际线程是可能存在的执行实例，线程可用性和续接取决于运行时。长期状态以工程文件及 Git 为准。

分发任务时只给相关 Reference、文档与范围，主控接收摘要、关键日志片段、证据路径及结论。接近上下文上限、换执行者或交回所有权时先落盘交接，附失败命令、预期、当前发现和继续动作。已有用户修改应记录可定位差异和归属。

恢复顺序为 `PROJECT_CONTEXT.md` → `PROJECT_BASELINE.md` → 模块 `MODULE_CONTEXT.md` → `HANDOFF.md` → `git status --short` 和 `git rev-parse HEAD` → 接口及资料变化 → 上次验证与剩余工作。检查基线、未提交变更、关联的 P0 和所有权后再继续。实际线程可续接时仍复核工程状态。只在用户授权的范围创建或持久运行独立会话。
