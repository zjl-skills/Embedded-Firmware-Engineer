# 工作模式与证据

## 选择工作边界

| 模式 | 可推进的工作 | 停止受影响工作的时机 |
| --- | --- | --- |
| A 严格交互 | 收集资料、扫描、准备方案和独立验证。 | 需求、硬件资源、架构、模块接口及关键实现方案的批准点。 |
| B 自主工程师 | 沿已有约定拆解、实现、审查、构建、测试、整理证据。 | P0、重大不确定性、用户需要作出的决策，或超出已有权限。 |
| C 高度自主 | 在授权范围内自行修复可恢复故障并完成集成与交付。 | P0、资料与目标冲突或权限边界。 |

新项目提示 A/B/C，用户暂未指定可按 B 开始独立、可逆的调查。模式切换记录在项目上下文，说明生效范围及仍在等待的决策。小型修复可以沿用仓库流程和项目证据，复用已存在的基线与现有测试入口。

## 记录证据的性质

| 性质 | 记录方式 |
| --- | --- |
| 已确认事实 | `DOC-ID`、版本、适用范围及定位，例如板号、页码、表或代码行。测量附环境、仪器、条件。 |
| 基于资料的推断 | 指明输入证据、推理和适用范围，注明下一步验证。 |
| 工程建议 | 写清代价、备选、风险和可验证的验收条件。 |
| 未确认假设 | 明写假设、影响、所有者、失效条件和补证行动。 |
| 待用户决策 | 提供相关资料、选项及各自影响，标记阻塞链路。 |

## 权威性随事实变化

- 当前批准的板卡、电路、工程和需求基线确定项目实际采用的配置。核对具体板号、板版次、料号、封装、芯片修订、SDK 和编译配置。
- 厂商 Datasheet 支持额定值及引脚能力，Reference Manual 支持寄存器和外设流程，对应 Errata 修正其列出的芯片修订和条件。器件手册支持外设地址、位定义、上电和总线时序。板级实连需核对网表、批准的原理图或可追踪的实物证据。
- SDK/HAL/LL/BSP 和官方示例佐证当前版本 API 与典型用法，结合头文件、构建输入和配置确认实际行为。RTOS API、协议和中间件按各自官方规范。成熟开源实现与工程经验用于形成备选和假设。
- 缺少资料时，列出需要的型号、版本、页码、项目配置或实测结果，同时推进能独立验证的工作。资料变更和不一致按 [资料治理与一致性](../02_document_analysis/consistency.md) 处理。
