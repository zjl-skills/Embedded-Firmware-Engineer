# 架构与接口

| 层 | 职责与边界 |
| --- | --- |
| L1 Hardware | 电路、芯片、信号、电源、外部器件和板级实测。工程事实来自确定的板和物料。 |
| L2 BSP / HAL | 板和芯片适配，外设实例、pin mux、时钟、复位、启动及厂商 API。 |
| L3 Driver | MCU 外设封装与外部器件抽象，通信状态、超时、错误归一化和设备能力。 |
| L4 Middleware | 协议栈、文件系统和第三方组件，借助明确的 port 和 OS 适配接口。 |
| L5 Service | 通信、数据、设备、故障、电源等面向应用的组合策略。 |
| L6 Application | 业务状态、调度和产品流程，通过 Service 或经约定的公开下层接口工作。 |

依赖由上往下沿公开接口。BSP/Driver 的 IRQ、回调和事件使用调用方提供的契约和上下文指针，底层不 include 业务头文件。OS 抽象以项目约定挂在 port 边界，应用、通用驱动和服务依赖抽象能力。单向规则同时检查代码、构建链接和配置；循环依赖通过提炼共同契约或协调器断开。应用不访问寄存器或厂商 HAL API。

## 模块设计和接口先行

模块设计写清职责、输入输出、数据结构、公用 API、错误模型、依赖和资源预算、初始化/生命周期、取消/超时行为、并发和 ISR 约束及测试要求。指明由谁分配、拥有和释放缓冲区，长度单位、溢出行为、调用前置条件、回调何时调用以及允许在哪个上下文。跨模块变更比较兼容性、迁移顺序、受影响方和回归项。

确认关键时钟、电源、DMA、IRQ、堆栈和带宽资源的唯一所有者或仲裁策略。公共接口由协调者批准版本，定义调用和数据语义后再并行分派实现。异常依赖或偏离通过 ADR 记录背景、备选、原因、影响、审批状态和去除条件，评审代码与构建约束的符合性。

## 复核

使用 [架构模板](../../templates/architecture/ARCHITECTURE.md) 和 [接口契约](../../templates/interface/INTERFACE.md) 提供设计证据。`check_architecture.py` 结合项目层、模块和 include 搜索路径，报告可解析的向上 include、配置的 L6 禁用模式和模块依赖环。评审预处理分支、工具链搜索、间接依赖、回调方向、运行时调用及资源所有权，给出脚本未覆盖的结论和证据。
