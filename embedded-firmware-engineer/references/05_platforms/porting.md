# 平台证据与移植

适用于 STM32、GD32、CH32、MM32、HC32、NXP MCU、Renesas MCU、ESP32 及适用的其他 MCU。将系列名作为检索入口，依据完整料号、封装、芯片修订、目标板和当期官方文档选择配置。关联供应商 SDK、HAL、LL、BSP、启动和链接版本；架构同源或封装相似均需逐项核对。

## 差异表和迁移顺序

1. 针对同一需求在源、目标建立证据列，记录核心架构和特权/异常模型、FPU/ABI、存储分区及启动、Boot/复位、时钟树和电源态。
2. 逐项映射外设实例、pin mux、电气、IRQ、DMA、缓存一致性、校准、芯片限制、库 API 和并发上下文。映射记录具体型号的官方表及板上连线证据。
3. 在 BSP/HAL、OS 适配与构建边界增加目标实现，保留 Driver、Service、Application 的复用接口。对确需变化的接口安排兼容期并记录 ADR。
4. 使用目标已有启动、链接、SDK 和工具链入口进行干净构建，检查 map 和启动向量。先用宿主验证通用行为，再分阶段进行目标链接、板级 bring-up、外设与系统验证。为跨平台重测保留旧平台基线。

关注端序、指针/数据宽度、对齐、ABI、缓存或原子指令的有效范围。与 BSP 关联的时钟、Flash 擦写行为、低功耗、IRQ 优先级、RTOS port 和异步 I/O 必须按目标重核。选型时同时评估时限、内存、外设、供电、采购寿命、工具链许可及移植风险。
