# C/C++ 与构建审查

## 代码与资源生命周期

- 明确 C/C++ 标准、目标 ABI 及例外，核对整数宽度、对齐、初始化顺序、结构布局、端序和 `extern "C"` 边界。协议与持久化采用明确编码。测试编译器升级、优化、LTO 后的行为。
- C 约定所有者、借用期、长度、释放方和错误路径。C++ 优先用 RAII 封装具备生命周期的资源，利用受控作用域管理锁和设备句柄。避免分配隐蔽、悬垂引用和静态初始化依赖。是否启用异常、RTTI、静态对象析构及动态分配须写入目标和预算，核对实际链接开销及失败行为。
- 裸机与 RTOS 都要明确 ISR 调用边界。只在任务上下文实施可能阻塞、分配或析构的操作。审查中断优先级、临界区最坏时间、原子访问、DMA 缓存与发布顺序。用目标架构证据确定 atomics 的适用性、编译输出和中断语义。复核锁序、超时、重入和任务退出。

## 启动、链接及测量

- 用实际启动文件核对 Reset、向量表、栈起点、`.data` 拷贝、`.bss` 清零、构造函数入口和跳转。链接脚本检查 MEMORY/SECTIONS、保留区域、NOLOAD、对齐、链接器断言和共享/持久化区域，结合 map 与镜像核对区域重叠、尺寸、地址和升级影响。
- 比较 GCC、Clang、Keil、IAR 的扩展、段属性、IRQ 语法、标准库及链接 GC。记录编译器版本、警告选项、优化、宏、ABI、浮点策略。用实际目标构建和静态分析定位实现差异，逐条复核预处理及内联汇编的假设。
- 用 map、链接器/编译器栈报告、静态调用上界和运行时高水位评估主栈、IRQ 嵌套、各任务栈。对间接调用和递归补手工上界。记录最坏负载、采样周期；堆报告包含峰值、碎片、分配失败及恢复。保留证据位置和测量环境。

MISRA 合规结论需要明确适用规则版本、已配置的检查工具和规则覆盖、人工检查及批准的偏离记录。普通代码风格或编译警告只提供其覆盖内的证据。[质量验证](verification.md)
